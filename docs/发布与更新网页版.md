## 后续修改

日常继续编辑原工作区 `game/project.godot`，即 `C:/Users/Hsq/Desktop/燕云”烽火连绵“/game/project.godot`。`publish/fenghuo-lianmian` 是独立的发布用 Git 仓库副本，准备脚本会从原工作区复制修改，请只在原工作区维护游戏。

1. 在 Godot 保存全部场景和脚本，按 F5 运行检查。新增模型、贴图、材质、音效等文件放在 `game/assets/` 的子目录；场景放在 `game/scenes/`，代码放在 `game/scripts/`。这些目录会同步到发布仓库。
2. 回到原工作区，双击 **`准备网页更新.cmd`**，看到“同步完成”后关闭窗口。它调用 Python 按白名单准备发布文件，不会自动提交或上传。已有云端构建，因此日常更新不必在本机手动导出 HTML。准备脚本也会同步唯一数值 Excel；如修改表中数值，应先运行 `python tools/export_config.py --prototype` 生成游戏使用的配置并检查结果，再准备发布。
3. 打开 **GitHub Desktop**，左上角 **Current repository** 选择 **fenghuo-lianmian**，**Current branch** 选择 **main**。核对 Changes 中是本次游戏文件，在 Summary 写例如“更新城门模型”，点击 **Commit to main**，再点击顶部 **Push origin**。这两个操作缺一不可。[GitHub Desktop 官方说明](https://docs.github.com/en/desktop/making-changes-in-a-branch/committing-and-reviewing-changes-to-your-project-in-github-desktop?platform=windows)
4. 打开 [Actions 页面](https://github.com/aki9911/fenghuo-lianmian/actions)，等待最新一次 **Build playable demo and deploy Pages** 的 build 和 deploy 均为绿色成功。它会测试、导入新资源、重新导出 Web 并发布。
5. 打开原试玩链接刷新。已经打开游戏的玩家需要刷新页面才会切换版本；如仍看到旧内容，按 **Ctrl+F5** 强制重新加载。不是在进行中的战斗里热替换模型和代码。

**试玩地址保持不变。** 每次成功部署覆盖网站当前版本，不需要重新创建仓库或给玩家换链接。构建失败时不会替换已发布版本，点击失败的任务查看错误后修复、重新提交推送即可。

新模型优先使用 `.glb`，并把贴图一同放入 `game/assets/`。直接导入 `.blend` 需要构建机器也安装 Blender，目前云端工作流只配置了 Godot；因此先从 Blender 导出 GLB 再引用更适合当前发布流程。[Godot 3D 导入说明](https://docs.godotengine.org/en/latest/tutorials/assets_pipeline/importing_3d_scenes/available_formats.html)

如果要在本机额外检查网页导出，可在原工作区运行 `./tools/export_demo.ps1 -WebOnly`。正常上传更新使用前面的双击准备脚本即可。

网页首页和操作说明位于发布仓库的 `web/index.html`。完整 `.wasm` 与 `.pck` 必须配套，不能只上传 `game.html`。GitHub Pages 已设置为 GitHub Actions 部署。
