# 编辑角色与相机

版本 v0.6｜更新 2026-11-13｜状态：灰盒已集成，编辑场景、物理与主场景功能检查通过；性能另行复测。以下按当前文件结构说明编辑方式，更换资产后仍需重新运行验证。

## 先找到要编辑的资产

在 Godot 4.7.2 导入 `game/project.godot`。以下路径均从 Godot 的 `res://`（也就是仓库的 `game/`）开始。

| 修改目标 | 文件或脚本 |
|---|---|
| 友军外观与碰撞 | `scenes/actors/ally_soldier.tscn` |
| 敌军外观与碰撞 | `scenes/actors/enemy_soldier.tscn` |
| 居民外观与碰撞 | `scenes/actors/civilian.tscn` |
| NPC 公共行为 | `scripts/actors/npc_controller.gd`，三种角色场景根节点共同引用 |
| 玩家外观、移动与朝向 | `scenes/actors/commander.tscn`；根节点脚本 `scripts/actors/player_controller.gd` |
| 背后跟随相机 | `scenes/actors/third_person_rig.tscn`；根节点脚本 `scripts/actors/third_person_camera.gd`，总览切换由主控衔接 |
| 城镇建筑与环境 | `scenes/wangfeng_town.tscn` |

友军、敌军、居民有各自场景，所以外观可以独立维护。场景中的每个实例共享其根节点引用的同一个 `.gd` 文件；实例仍各自拥有位置、身份、血量及命令状态。编辑公共脚本会影响所有引用它的角色，不是只修改编辑器当前选中的那一个人。

## 替换 Visual 模型

1. 在左侧「文件系统」双击要改的角色 `.tscn`，打开它自己的场景页；在顶部切到 **3D**。编辑源场景，不编辑运行中「远程」场景树。
2. 在场景树选根节点，在右侧 **Inspector / 检查器 → Script** 确认 NPC 仍引用 `npc_controller.gd`；玩家 `commander.tscn` 则保留 `player_controller.gd`。保留根节点的类型、名称和 Script，以及根下的 `Visual` 容器与 `CollisionShape3D`。
3. 当前 `Visual` 是 `humanoid_visual.tscn` 的实例。若其子节点不可编辑，右键 `Visual` 启用 **Editable Children / 可编辑子节点**；展开后隐藏旧占位网格 `Body`、`Head`、`Hat`、`Spear`、`FaceDirection`。保持 `Visual` 本身可见，否则新模型也会被隐藏。若实例子节点不能删除，保留隐藏即可；不要为删除旧网格而删掉角色根节点。
4. 将已导入项目的模型场景从「文件系统」拖到 `Visual` 下面。模型的网格、骨骼和动画节点可以保留在自己的子树中。若仍显示旧模型，确认旧占位子节点已经隐藏或删除。
5. 选新模型子节点，在检查器 **Transform** 调整 Position、Rotation 和 Scale，让脚底贴地、大小和原角色接近、朝向与原占位模型一致。模型方向相反时旋转模型子节点，保留角色根节点朝向由控制器管理。缩放外观不会自动修改碰撞体。
6. Ctrl+S 保存角色场景，按 F5 运行主场景，观察对应敌军、友军或居民是否使用新外观。角色子场景 F6 可用于单独预览，但没有完整战斗上下文，不能代替主场景行为验证。

更改角色源场景会影响该场景以后生成的实例。只想修改一种类型时，编辑对应角色场景；直接修改 `humanoid_visual.tscn` 会影响引用它的敌军、友军、居民和玩家外观。若只想修改一份共享材质或网格资源，在检查器该资源的菜单中使用 **Make Unique / 唯一化** 后再调整。资源唯一化不会自动复制公共 `.gd` 脚本。

## 调整碰撞尺寸

选中角色的 **CollisionShape3D**，在检查器展开 **Shape** 资源。胶囊体使用 Radius、Height 调整半径与高度；盒体使用 Size 调整尺寸。再调整碰撞节点的 Position，让碰撞形状覆盖身体并与脚底相符。

保留 `CollisionShape3D` 节点及其有效 Shape，不要只换模型却留下明显过大的旧碰撞体。优先修改 Shape 尺寸，而不是非均匀缩放角色根节点。若 Shape 被其他场景共享，先按需要唯一化，再改尺寸，以免敌军和友军一起变大。

运行主场景，使用 Godot 的「调试 → 可见碰撞形状」检查实际位置，验证建筑、门道和部队之间的碰撞。外观尺寸、物理碰撞与模拟中的攻击距离是不同设置：换大模型不会自动扩大伤害范围，改碰撞体也不能另扣一次伤害。双方应通过公共控制器与中央模型同步。

## 修改公共脚本

要修改所有 NPC 的共同移动或战斗处理，打开 `scripts/actors/npc_controller.gd`。不要为每一个敌军实例复制一份同内容代码。需要敌友差异时，由场景模板参数、实体身份或命令分支表达；需要改变人数、士气或胜负时，维护中央 `BattleModel` 的规则。

根节点检查器中仅调整脚本实际导出的属性。当前控制器提供 `template_id`（模板标识）、`combat_style`（兵种方式）、`speed_multiplier`（速度倍率）和 `damage_multiplier`（伤害倍率）；这些是场景调试参数，基础数值仍来自导出配置。若导出字段改变，以脚本与模块契约为准，不在此教程另维护一份可编辑数值表。

公共行为由中央模拟调度。不要额外加入每个实例独立推进的战斗计时或重复伤害；也不要让角色离开镜头后停止攻城、伤亡或撤离逻辑。运营居民仅代表劳作表现，复制居民模型不能增加名册人口或生产量。

## 相机与操作键位

默认第三人称背后跟随，进入自由行走时捕获鼠标。下面是当前已接入的键位。

| 输入 | 行为 |
|---|---|
| 鼠标移动 | 捕获状态下直接转动视角，无须按住右键 |
| WASD | 相对镜头方向移动；阶段部署时也允许行走 |
| M | 切换背后跟随与总览地图；总览可看库存、选择地图 |
| 滚轮 | 仅承诺总览地图缩放；第三人称距离滚轮调节尚未定为本版功能 |
| Esc | 先关闭当前界面；自由行走时释放鼠标 |
| 点击游戏画面 | 自由行走时重新捕获鼠标 |
| E | 到达建筑交互范围后显示对应部门功能 |
| H（交战中） | 打开或关闭指挥轮盘，不暂停战斗 |
| 1～5（轮盘中） | 选队，再点击跟随、守卫阵位、推进；推进目标为玩家朝向前方 12 米 |

修改跟随相机时打开 `scenes/actors/third_person_rig.tscn`，选根节点 **ThirdPersonRig**，在检查器调整实际导出字段：`distance` 为跟随距离，`sensitivity` 为鼠标灵敏度，`focus_height` 为瞄准玩家的高度，`pitch` 为初始俯仰。相机脚本会将 `distance` 写入 `SpringArm3D.spring_length`，因此持久调整跟随距离应改根节点字段；改变视野角则选择 `SpringArm3D/Camera3D` 调整 FOV。鼠标移动会改变当前俯仰，俯仰上下限当前在 `third_person_camera.gd` 中。

玩家行走由 `scripts/actors/player_controller.gd` 管理；选 `commander.tscn` 根节点可看到 `move_speed`、`gravity`。相机捕获、Esc、M 和菜单上下文由主控衔接，不能仅修改相机位置就视为完成键位接线。避免在相机脚本里另写一套人口或战斗规则。

每阶段部署都需到指挥所办理：NPC 战斗与生产冻结，玩家可以步行返回。选队点合法地面会立即改位，确认开战才恢复自主交战；战斗轮盘的推进则是实时行军。M 的地图选择和库存查看不能绕过建筑交互距离，离开建筑后也不能通过旧面板继续雇佣或制造。

## 保存后检查

- 检查三种角色根节点的 Script、`Visual` 和 `CollisionShape3D` 保留，主场景实际使用修改后的资产。
- 检查第三人称、M 总览、Esc、重新捕获鼠标和 E 面板之间切换正常，点击 UI 不同时触发攻击或移动指令。
- 检查部署时玩家可行走而 NPC 与经济冻结，点地立即改位；H 轮盘时则持续交战。
- 检查更换模型或碰撞体不会增加人员、突破突袭敌军 100/友军 30、正常 100/50 上限、重复伤害或改变屏外结算。

本版编辑场景检查 664/0、物理检查 65/0、主场景集成 51/0；证据由主 agent 记录到 [验证记录](../production/validation.md)。以上清单供每次修改资产后回归，不代表任意替换模型都会自动通过。性能须以实际角色场景与碰撞配置重新测量，60 秒复测及长期负载结果单独记录。
