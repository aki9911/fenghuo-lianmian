# 战报与长期活动

版本 v0.5.2｜负责人：活动与战报策划。

本版实现：单场事件、去重结算、本机多场功勋和战后军报界面已经接通；军民人数可与开战基准对账。根据用户决定，v0.5.2 移除战报 JSON 导出按钮及独立文件导出逻辑；本地战报与累计功勋仍随镇务存档保存。全服聚合、模拟战区汇总页、支援记分、实时预估功勋、每日榜单以及后续故事改变物资尚未实现，以下对应内容仍是后续目标。模拟运输仅验证发车、到账及一次有限回赠。

## 战报定义

正式目标是全服共享战区。当前 Demo 只提供真实单场、本地累计及明确标注的模拟邻镇汇总，不将模拟数据表述为在线全服结果。

| 指标 | 定义及时间口径 |
|---|---|
| 击败敌人数 | 已确认击败的唯一敌军实体累计数，包括玩家、军队和器械贡献 |
| 残存小镇数 | 当前仍由我方控制的据点数量，是状态快照，不累加历次胜利 |
| 军民牺牲数 | 确认死亡人数，按开战时居民/军人身份归类；转兵不重复统计 |
| 敌人攻势残余 | 已投入且未被击败/溃退的存活敌军快照；未生成的未来敌军不算人数 |

持续刷新后无法再定义“固定初始兵力减去击杀＝全场剩余兵力”。保留用户需要的残余人数指标，但界面标明“已投入敌军残余”，不暗示这是无限刷新源的最终剩余人数。

另显示当前敌人士气和仍在进攻的战场数，作为剩余进攻压力参考。若后续需要有限的全服远征军预算，必须另开战略层设计，不能在本版悄悄恢复单场兵力池。

结算时：士气归零，尚存的已生成敌人转为溃退；失败而敌军仍有士气，存活敌人转为占领驻军或残余攻势快照，不继续在后台无限生成。跨阶段离场只变状态，不加击杀。

人员账：开战军民 = 确认牺牲 + 存活 + 失踪；伤员是存活子集。分别列出留镇、撤出、受伤、牺牲和失踪，不将未撤离人数当作死亡。预备队转兵仍使用同一个 person_id。

## 功勋与支援

保存击败敌军、破坏粮草仓、保全民众、守城、物资到账等事件，实时显示预估功勋，战报结算后确认。事件号去重，读档/切阶段/重复提交不得重复记账。分值先留待数值设计，不继承 v0.2 的试填分值。

持续刷新可能延长可刷杀敌时间。原型不引入未确认的硬性时限，但记录战斗时长、士气变化和杀敌速率；军需或刷兵更新不得让士气持续恢复形成无尽刷分。正式榜单上线前再决定计分上限与异常处理。

支援按有效到账和实际贡献统计，模拟邻镇支援单列。正式版须防止同一货物往返刷分，需来源追踪、合理计分上限和资源价值表。军队驰援后续设计所有权、伤亡归属、返还和贡献，不在当前 Demo 开启。

功勋累计保存，政府支援仅保留未来解锁方向，当前不开发支援技能树。

## 每日排名与后续故事

后续按北京时间每日 00:00—24:00 统计新增功勋、有效杀敌、有效支援三榜；历史累计功勋不清零。日切基于权威时间，不使用玩家设备时钟裁定。真实排名和全服服务在后续版本实现。

核心 Demo 保留一张后续军报，依据城镇保有与军民撤离选择“坚守补给”或“收容重建”文本，可改变下一场模拟邻镇提供的物资种类。完整剧情分支和数值门槛后续配置，不在多个文档复制分支条件。

## 本册验收

- 一个敌人和一次支援只有一个有效记分结果；死尸清理、预生成预约及离开镜头不增加击杀。
- 残存小镇反映最新状态；同镇多次胜利不变成多个小镇。
- 无限后续刷兵不显示为固定剩余总兵力；已生成存活数和累计击杀可同时正确显示。
- 初局 150 人发生转兵、受伤、牺牲、撤离后总账仍可对上；战报能追溯准备、突袭、杀敌、撤离对结果的影响。
