真实场景撤离在镜头外运行，150 人全部撤出，用时 106.7 模拟秒。集结点 `(0,11)`，路线 `(5,10) → (12,14) → (12,21) → (21,22)`；坐标采用 `(x,z)`。此结果证明受测场景的撤离闭环，不代表正常战斗胜率或帧率。

v0.5 在既有经济与战斗模型上拆分玩家、相机及 NPC 控制器。`town_state.gd` 保留人口、雇佣和经济调度；`battle_model.gd` 保留阶段、真实名册、总人数、士气、事件与结算；`world_view.gd` 负责场景绑定与角色表现衔接；`main.gd` 负责输入上下文、中文界面与模块衔接。具体方法签名由 [模块契约](../production/implementation_contract.md) 跟随实现维护，不能将下文职责表当作已存在的 API。

城镇沿用可在编辑器查看的 `scenes/wangfeng_town.tscn`，由 `main.tscn` 实例化。角色改为独立可编辑场景；运行时应使用这些场景资产，不能另生成一套外观覆盖编辑结果。职能建筑与指挥所的交互位置应从场景读取。中文操作面板仍由主控创建；教程见 [编辑角色与相机](../docs/编辑角色与相机.md)。

|---|---|
| `scenes/actors/ally_soldier.tscn` | 友军外观、碰撞体及场景模板参数 |
| `scenes/actors/enemy_soldier.tscn` | 敌军外观、碰撞体及场景模板参数 |
| `scenes/actors/civilian.tscn` | 运营居民及撤离代表模型；不凭模型数量记人口 |

| `scripts/actors/third_person_camera.gd` | 挂载 `scenes/actors/third_person_rig.tscn`，负责背后跟随；主控衔接 M 总览切换，相机操作不改模拟状态 |

每个场景保留根节点公共 Script、`Visual` 子节点和 `CollisionShape3D`。外观替换在 `Visual` 下完成；碰撞尺寸在碰撞 Shape 资源内调整。所有实例共用相同 `.gd` 代码，但各自持有身份、状态和模板参数。中央模型负责人数及结算，个体脚本不得另外扣一次士气或另生成一套人员名册。

中文字体内嵌 NotoSansSC。桌面存档使用 `user://savegame.json`，战报导出使用 `user://local_reports.json`；Web 版战报通过 JSON 下载，不能假定浏览器可写项目目录。源码仓库 `aki9911/fenghuo-lianmian` 已公开，浏览器版已部署至 https://aki9911.github.io/fenghuo-lianmian/ 。CI 构建和匿名资源访问已验证；浏览器键鼠试玩与性能尚未自动验证，详见发布说明和验证记录。

## 目标规模

第三人称背后跟随的低多边形 3D，M 切换总览地图。运营只显示建议 15 个代表模型，人口、岗位和产出在数据层实时计算。正常战斗必须验证 100 个敌军实体+50 个友军实体+玩家；撤离再加入最多 10 个居民队列表现，共最多 161 个移动主体。突袭为最多 30+30+玩家。

这是新的目标负载，不是已经实测的性能保证。撤销 v0.2 的 4 个友军代理+24 个敌人的缩减目标。若遇到性能瓶颈，先优化逻辑和表现，再把实测结果交给用户决定是否降规模，不能静默改回代理战斗。

## 建议实现

运营以一个经济调度器更新所有作业，不为 100 名居民各建生产脚本。工作模型的动画与寻路只提供视觉表现，不驱动资源结算。使用有效模拟时间累计，不把帧数当秒数。

战斗按分队共享命令目标，每个战斗实体保留独立人数、生命和命中状态。公共 NPC 控制器包含行为逻辑，由中央模型按有效模拟时间调度；不能在模型与节点 `_physics_process` 中各执行一份伤害或移动。AI 决策可分组更新，路径只在必要时重算。简化碰撞体，限制局部避让范围，避免所有角色彼此进行复杂碰撞检查。Godot 官方建议分散路径请求并避免每帧不必要重算，可作为优化依据。[官方导航优化文档](https://docs.godotengine.org/en/stable/tutorials/navigation/navigation_optimizing_performance.html)

相机切换和屏幕可见性只影响观察与表现，不停用屏外个体的权威战斗、攻城、士气、人数和撤离逻辑。新增独立节点与碰撞体后的性能须重新测量，不能沿用旧 MultiMesh 表现的帧率结论。

若使用敌人或投射物对象池，复用时必须生成新的战斗实体 ID、清空旧生命、目标、命令和伤害状态；不能让旧击杀事件附着新角色。尸体、粒子和箭矢分别限制保留量。远程命中先采用轻量范围/射线判定，不做全场刚体箭雨。

阶段门、街垒和破损城门使用预制状态与已知通路。木墙和街区共用基础控制器，阶段差异由目标与规则配置表达。只保留一个战斗管理器决定士气、刷兵和胜负，避免重复切阶段。

## 模块和时间

- `PopulationRegistry`：唯一人员、岗位、身份、健康和地点。
- `EconomyScheduler`：实时作业、材料锁定和产出。
- `HiringService`：一次性扣费、岗位容量、转岗事务。
- `BattleDirector`：阶段、部署暂停、士气、刷兵预约与结束。
- `BattleRoster`：常备军、预备补员、阶段上场名册。
- `ReportRecorder`：去重事件、战果及功勋输入。
- `ConfigLoader`：读取校验后的 JSON 配置，锁定批次和战斗版本。

经济时间只在运营状态前进，战斗时间只在实时交战状态前进。部署暂停两者都停止，但玩家控制器、相机和指挥所 UI 继续响应。部署点击合法地面直接修改选中分队的位置并同步显示，属于显式布置，不推进 NPC 模拟；确认开战才恢复自主行为。存档保存剩余进度而非用系统时钟补发收益。

M 总览可查看库存和选择地图，不负责切换运营/部署/战斗状态。H 轮盘在交战时下达跟随、驻守、推进命令，不暂停计时或攻击。建筑 E 面板的开启与实际提交都检查玩家距离；相机远近、地图选择、旧面板焦点不能代替距离校验。指挥所处理部署及接敌，军需所处理制造，避免把所有部门按钮堆在常驻 HUD。

## 实施顺序

1. **角色与相机：** 建立三种角色场景及公共 NPC 行为脚本，拆出玩家和第三人称相机，验证编辑器资产能在运行中复用。
2. **交互入口：** 接入建筑前 E、军需所制造、指挥所接敌及部署，接入 M 总览和逐次距离校验。
3. **部署与指挥：** 部署期间玩家可移动、NPC 和经济冻结；点地即时改位；确认开战；H 实时轮盘三种分队命令。
4. **完整回归：** 复核 30/30、100/50、四阶段、士气、名册、撤离、战后与战报；随后进行新架构 UI 截图与性能实测。

## 验收场景

| 场景 | 验收重点 |
|---|---|
| 运营持续 60 秒 | 不同帧率产出一致，15 个代表模型不决定产能 |
| 四队雇佣满员 | 占 80 居民，其余 20 可采集；第 21 人被拒绝 |
| 钱币不足/取消批次/仓满 | 无重复扣款或负库存，有明确状态 |
| 50 军人减员 10，再转入 10 预备队 | 90 居民+50 军人，存活总量 140 |
| 多入口同时刷兵 | 敌军活跃数始终不超过本阶段 30 或 100 |
| 阶段暂停 60 秒 | 玩家可步行到指挥所，NPC 不自主移动，不刷新、攻击、占点、撤离或生产 |
| 部署即时改位 | 选队点合法地面后立即更新真实位置及显示，确认开战不再重放移动或重置位置 |
| 建筑 E 与距离 | 只显示当前建筑功能；远处、离开后的旧面板、M 总览均不能绕过距离 |
| 第三人称与 M 总览 | 默认背后跟随；总览可看库存及选择地图；来回切换不改变人员和模拟时间规则 |
| H 轮盘与 1～5 队 | 跟随、驻守、推进只控制所选队；展开时仍发生有效交战；不会瞬移或补兵 |
| 替换 Visual 和调整碰撞 | 角色根节点公共脚本保留，替换结果在运行中可见；碰撞不穿建筑且不重复造成伤害 |
| 屏外部队 | 攻城、刷新、伤亡与撤离照常模拟，相机切换不重置部队 |
| 士气归零同刻仍有生成预约 | 预约取消，敌人不在结束后继续出现 |
| 对象池循环复用 | 不继承旧伤害状态，不重复记同一击杀 |
| 150 基准撤出 120/119 人 | 未触发其他失败条件时分别小败/失败 |
| 同一战报重复提交 | 功勋、牺牲、战利品不重复累计 |

以上清单用于本版及后续变更回归，已有功能检查结果见本册开头。新架构 60 秒性能复测由主 agent 单独记录；性能基准需包含实际 CPU、GPU、内存、渲染器及导出版本。建议 1080p 平均 60 FPS、99 分位帧耗时≤33.3ms 作为初步目标；测试 151 人交战、161 主体撤离、持续刷新与尸体清理，运行至少 10 分钟观察 CPU/GPU/内存趋势。该长期目标尚未完成验证，不将文档数字或功能通过数当作达标结论。

若 CPU 受限，优先降低非关键 AI 决策频率并优化路径与碰撞；若 GPU 受限，先调整骨骼、阴影、粒子与绘制成本。优化必须保留真实 100/50 战斗人数和命中状态，规模变更另行决策。
