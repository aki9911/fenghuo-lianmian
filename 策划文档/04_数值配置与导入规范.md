# 数值配置与导入规范

版本 v0.6｜负责人：运营与数值策划；主 agent 审核数据接口。此次变更为用户确认的突袭初始人数、上限及增援时序；生产效率与经济人口规则不变。

## 配置源与工作簿

确认数值来源：[烽火连绵_数值配置_v0.3.xlsx](../outputs/fenghuo_v03/烽火连绵_数值配置_v0.3.xlsx)。现已实现 `tools/export_config.py`：构建时读取 XLSX 常量、校验并生成 `game/data/runtime_config.json`，Godot 启动时加载。服务端尚未实现。

原型模式 `--prototype` 只为 Excel 未定字段使用 `game/data/prototype_overrides.json`；尚未确认的额外战斗与初始资源参数也在此文件明确标记为原型建议。v0.6 将已确认突袭参数写入现有「全局参数」表，通过新增 `section` 列映射到 `globals` 或 `combat`，无需另建参数注册表。生成配置包含工作簿 SHA256 和逐字段来源，覆盖值不能替换 Excel 已有常量。

`combat` 合并顺序为先读显式原型参数，再逐项采用 Excel 常量；未确认的 Excel 空值仅在原型模式下允许查找同名覆盖值。标为“已确认”却留空属于源数据错误，任何模式都拒绝用覆盖值补齐。来源键为 `combat.<id>.value`，确认参数记录 `xlsx (已确认)`，原型参数记录 `prototype_overrides (原型建议)`，不能把整个 combat 区块一概标为原型。严格模式 `--strict` 不加载覆盖文件，发现仍未配置的有效字段时退出码为 2，保留上一份运行配置与工作簿；当前雇佣、效率等仍有未定项，严格模式预期拒绝导出。

| 工作表 | 用途 |
|---|---|
| 产能预览 | 选择示例投入人数与时长，引用作业表计算工作量、理论完成批次与产物，不导入游戏 |
| 全局参数 | 初始人口、阶段上限、士气、表现模型、逻辑步长；通过 section 区分 globals、combat 和停用项 |
| 雇佣岗位 | 四部门 ID、人数上限、单人雇佣费和建筑入口 |
| 实时作业 | 采集、制作、修缮、救治、清扫的工作量、单人效率及每批产物 |
| 配方消耗 | 每种作业逐行列出投入物品与每批数量，一个配方可有多个输入 |

状态统一为“已确认”“原型建议”“待定”。已确认数值来自用户决策；原型建议为明确可调整的设计初值；待定数值留空。空白与合法的 0 必须区分。制作效率和雇佣费用尚未给出，不能把旧版回合数值强行除以秒数当作定稿。

## 稳定字段

全局参数：`id, name, value, unit, status, note, section`。`section=globals` 输出到全局参数；`combat` 输出到战斗参数；`deprecated` 仅保留历史说明、不导出、不要求补空值。旧工作簿缺少 section 时按 globals 处理；未知分组直接拒绝导出。同表 ID 保持唯一。

雇佣岗位：`id, name, max_workers, hire_cost, building_id, status`。

实时作业：`id, team_id, name, work_required, rate_per_person_sec, output_id, output_qty, status`。

配方消耗：`job_id, item_id, qty_per_batch, status`。同一 job_id 可多行，不允许重复 job_id+item_id；无原料的采集任务无需消耗行。

每张导入源表第 1 行为英文机器字段，第 2 行为中文说明，数据从第 3 行开始，整行空白跳过。说明列和状态列不成为运行时战斗规则。ID 采用小写 ASCII 下划线；不要改 ID 来改显示名称。

`work_required` 单位为工作量/批，`rate_per_person_sec` 为工作量/(人·秒)，`output_qty` 为物品/批或修复点/批。所有时间在导出数据中使用秒，人数是整数；百分比使用小数，如 0.3 和 0.8。货币单位暂定游戏钱币，不与现实货币关联。

工程类输出 `wall_hp/street_hp/evac_hp` 是修复目标工作结果；医疗的 `healed_person` 受真实伤员数限制；清扫的 `salvage_unit` 受战利品池限制。预备队只登记和转兵，没有“每秒产出士兵”的作业。

## 产能计算与材料结算

`理论工作量 = 人数 × 单人每秒效率 × 秒数`；`理论批次 = floor(理论工作量 / 每批需求工作量)`；`理论产物 = 理论批次 × 每批产量`。

预览假设满工、无材料/仓容限制，只用来比较产能；游戏结果还要受健康、任务分工、已锁材料、仓容和目标状态限制。必填数值缺失时预览显示“待配置”。模板中的投入人数和时长是试算输入，不是已确定生产效率。

填写作业行全部必填数值后，将该行状态从“待定”改为“原型建议”或“已确认”，才启用产能预览。若提前启用但正数必填项仍空缺或为零，显示“参数无效”，不输出虚假产能。预览按作业 ID 精确匹配；新增作业时需扩展预览的匹配范围和行，不复制硬编码数值。

普通阶段刷新间隔/批量、单兵士气扣减及城门通行速度仍使用原有参数与原型覆盖。后续敌军类型增多后再评估独立兵种表，不预先建立大量空表。

## v0.6 突袭阶段参数

以下均来自用户最新确认，唯一可编辑源为 Excel「全局参数」表；运行时按对应 section 导出。

| 运行参数 | 已确认值 | 含义 |
|---|---:|---|
| `globals.raid_enemy_cap` | 100 | 突袭敌军同时在场上限；允许超过初始 30 人 |
| `combat.raid_initial_enemies` | 30 | 突袭开战初始敌军 |
| `combat.raid_reinforcement_start` | 180 | 开战后首次增援时刻，单位秒 |
| `combat.raid_reinforcement_interval` | 60 | 首次之后的增援间隔，单位秒 |
| `combat.raid_wave_first` | 10 | 180 秒增援人数 |
| `combat.raid_wave_second` | 10 | 240 秒增援人数 |
| `combat.raid_wave_third` | 15 | 300 秒增援人数 |
| `combat.raid_wave_repeat` | 20 | 360 秒起，每 60 秒的增援人数 |

突袭友军上限仍为 30；正常阶段敌我上限仍为 100/50。增援时间使用该阶段实际交战秒数，部署暂停不推进计时；增援不能使敌军在场数超过 100，补兵不恢复士气。无伤亡情况下，开战及 180/240/300/360/420 秒后的敌军数量依次为 30/40/50/65/85/100。后续刷新和士气停止规则由战斗分册及实现维护。

旧 `raid_spawn_interval` 与 `raid_spawn_batch` 行保留，但 section 改为 `deprecated`，说明列注明 v0.6 停用。它们不再出现在运行 globals 中，也从原型覆盖移除；第一阶段不再使用固定短间隔补缺逻辑。`battle_spawn_interval`、`battle_spawn_batch` 仍用于普通阶段，不受这次迁移影响。

友军默认有限追击；H 的全军固守命令取消追击并原地不动。第一阶段敌军在粮仓周边巡逻防御，不攻门，也不出防区追玩家。行为规则是用户确认，以下半径仅为原型调试值，保留在 `prototype_overrides.json` 的 combat 中，**不是用户确认数值**：

| 原型参数 | 原型值 | 用途 |
|---|---:|---|
| `ally_pursuit_radius` | 8 | 友军有限追击半径 |
| `raid_guard_radius` | 10 | 突袭守军防区半径 |
| `raid_patrol_radius` | 6 | 突袭守军巡逻半径 |
| `raid_detection_radius` | 8 | 突袭守军侦测半径 |

当前均使用游戏世界距离单位；调半径不得扩大人数上限或使固守命令失去原地驻守约束。既有制造、雇佣、配方和产能预览不随突袭规则修改。

## 导入方案

构建期读取 XLSX→校验→输出 UTF-8 JSON→Godot 加载快照已经实现；游戏运行时不依赖 Excel 公式引擎。JSON 为运行输入，不另维护同内容 CSV。

源数据区只填常量，公式只在产能预览。导出只读取声明字段，并带 `schema_version`、`config_version`；导出失败不覆盖上一份有效配置。模板里标为待定的必填行必须阻止正式导出，不能默认补 0。

基础校验：唯一 ID、合法引用、数量非负、人数整数、需求工作量/单人效率为正、阶段人数上限合法；四部门最多 80 名居民、初始军民 150。突袭敌军上限与普通敌军上限均为 100，突袭初始敌军 30 不得大于上限；增援起点、间隔与各批人数必须为正整数，半径必须为正数。新生产批次采用新配置，已开始批次锁定旧版本；单场战斗锁定开战时参数，避免热更新改变进行中的胜负条件。

`check_project.py` 中的规则常量是验收断言，不是供策划编辑的第二份数值表：它检查最新已确认的 100 上限、30 初始人数和增援时序，并检查来源为 Excel 已确认；不再要求旧突袭短间隔字段。验收须包含恶意覆盖确认值的负例、停用字段不输出、缺少当前有效必填值拒绝导出、严格导出失败不覆写上一份配置，以及经济表内容/格式/公式保持不变。

## 协作与维护

Excel 由运营与数值策划单人写入。战斗和活动策划提交参数 ID、旧值、建议新值、理由和验证场景；主 agent 检查连带影响后再合并。每次发布同时更新分册版本与工作簿版本；不要产生多个同名“最终版”作为并行配置源。
